# DocuMind: Chat with Your PDFs

Upload a PDF and ask questions about it. Answers are generated by an LLM from the most relevant parts of the document, streamed live, and show the source passages (with page numbers) so you can verify them.

**Stack:** Next.js (TypeScript) · FastAPI (Python) · PostgreSQL + pgvector · OpenAI API

```
Browser (Next.js)  ──HTTP──▶  FastAPI  ──▶  PostgreSQL + pgvector
   upload / chat              │              documents, chunks (+ embeddings)
                              └──▶  OpenAI  (embeddings + chat completion)
```

## Run it

You need: Python 3.11+, Node 18+, Docker, and an OpenAI API key.

```bash
# 1. database (Postgres with the pgvector extension)
docker compose up -d

# 2. backend
cd backend
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env          # then put your OPENAI_API_KEY in .env
uvicorn app.main:app --reload --port 8000
# API docs: http://localhost:8000/docs

# 3. frontend (new terminal)
cd frontend
npm install
cp .env.local.example .env.local
npm run dev
# open http://localhost:3000
```

Run the tests: `cd backend && pytest`

## How it works (the RAG pipeline)

**Upload** (`POST /documents`)
1. `ingest.py` extracts text page by page with PyMuPDF.
2. `chunking.py` splits each page into ~1000-character chunks with 200 characters of overlap (so a sentence on a boundary is not lost).
3. `embeddings.py` sends the chunks to OpenAI (`text-embedding-3-small`) and gets back a 1536-number vector for each chunk. Similar meaning gives similar vectors.
4. Chunks, page numbers and vectors are saved in Postgres (`chunks` table, `vector(1536)` column) inside one transaction. An HNSW index makes similarity search fast.

**Ask** (`POST /chat`)
1. The question is embedded with the same model.
2. `rag.py` runs `ORDER BY embedding <=> question_vector LIMIT 5`. `<=>` is pgvector's cosine distance, so this returns the 5 chunks closest in meaning.
3. Those chunks are put into the prompt as numbered passages. The system prompt tells the model to answer only from them and to cite `[1]`, `[2]`, or say it cannot find the answer.
4. The answer is streamed back as newline-delimited JSON: first the `sources`, then `token` events, then `done`. The frontend (`lib/api.ts`) reads the stream and appends tokens as they arrive.

## Project layout

```
backend/app/
  main.py        API endpoints, streaming response
  ingest.py      PDF -> pages -> chunks -> embeddings -> database
  chunking.py    overlapping text splitter
  embeddings.py  OpenAI embedding calls (batched)
  rag.py         vector search + prompt building + streamed answer
  db.py          schema, pgvector index, connections
backend/tests/   chunking, prompt and API tests (no DB or OpenAI needed)
frontend/
  app/page.tsx         document list, upload, delete
  components/Chat.tsx  chat UI, streaming, source viewer
  lib/api.ts           API client + stream reader
```

## Good extensions (try these yourself)

- Add login (JWT) and scope documents per user.
- Send previous messages to the model so follow-up questions work.
- Hybrid search: combine pgvector with Postgres full-text search.
- Compare chunk sizes (500 / 1000 / 1500) and see how answer quality changes.
- Support DOCX or web pages besides PDF.
- Store the original PDF in S3 and show the page next to the answer.

## Limits

- Scanned PDFs (images without text) are rejected; they would need OCR.
- No authentication: anyone who can reach the API sees all documents.
- Each question is answered independently (no chat memory yet).
